외부 API 장애 원인 추적용 SRE 모니터

2026.10 · 개인 프로젝트 · github.com/hyunsuhahaha/public-api-monitor · pamon.hyunsuhahaha.workers.dev

GoSQLite · LitestreamGCPDockerCaddyCloudflare Workers · D1GitHub Actions

장애 판정

  • 공공 API는 실패해도 HTTP 200을 줌. 응답 본문의 결과 코드까지 읽어서 판정하고, 키 미등록·호출 한도 같은 우리 쪽 문제는 장애에서 뺌.
  • 인증이 필요한 API는 키 없이 호출해서 그 서비스가 직접 거절하는지로 확인. CDN이 대신 준 403이나 점검 페이지는 정상으로 안 침.
  • API마다 최근 응답으로 평소 속도를 학습해서 느림 기준을 정함.

원인 추적

  • 요청을 DNS·TCP·TLS·서버 대기 구간으로 나눠서 어디서 멈췄는지 기록 (Go httptrace).
  • 타임아웃이 나면 같은 요청을 한 번 더 길게 보내서, 일시적으로 걸린 건지 서버 전체가 느린 건지 구분.
  • 같은 시각 다른 서버, 같은 기관 다른 API 결과와 비교해서 기관 서버 문제인지 네트워크 문제인지 근거를 남김.

SLO · 장애 대응

  • API별 SLO, 에러 버짓, burn-rate. 장애 기록, 포스트모템 초안, 런북.
  • 하룻밤 돌려보니 응답 형식 변경 알림 6건이 다 오탐이었음. 에러 응답은 학습에서 빼고, 느림 기준은 정상 응답으로만 계산하게 고침.

운영

  • GCP VM 한 대에서 5분마다 검사하고 결과를 정적 사이트로 내보냄 (systemd 타이머, Docker, Caddy).
  • SQLite를 Litestream으로 GCS에 실시간 복제.
  • Cloudflare Workers를 공개 입구로 두고 접속 기록은 D1에 저장.
  • 서버와 분리된 GitHub Actions에서 5분마다 사이트가 최신인지 확인.
